# Receipts list, table, image cache

- **Filters** are pure logic in `lib/receipt-filters.ts` (`parseFilters`/`filtersToParams`, `matchReceipt`, `sortReceipts`, `groupByMonth`, `parseAmountInput`, `activeChips`), applied as a `useMemo` over the loaded array — client-side, no debounce, native `Date` via `parseDateOnly`. Period defaults to `all`, not the mockup's "this month", so older receipts don't look lost.
- **Filter URL** (`?q&period&from&to&min&max&type&sort`): same pattern as `?receipt=` — read once from `useSearchParams()` as initial state, written by the *one* `replaceState` effect that also writes `receipt` (two effects would overwrite each other's params). Defaults are omitted, invalid values (including impossible dates like 2026-02-31) fall back to the default, a `period=custom` without a valid date loads as `all` and an empty custom range is inactive (no chip, not written), `min`/`max` are dot-decimal in the URL regardless of `number_format`, and can't be negative — refunds aren't filterable by negative bounds, deliberate. A navigation to `/receipts` from elsewhere (sidebar "Receipts", a dashboard link) changes `searchParams` without a remount: the page keeps the last query it wrote in a ref and re-reads filters and `?receipt=` when `searchParams` differ from it.
- **`?upload=1`** (mobile upload button, dashboard empty state) opens the create dialog, read like `?receipt=`: initially and in the "outside navigation" effect; `upload` is removed from the URL (`replaceState`, `lastQuery` updated) as soon as it is consumed, independent of the list load — otherwise a failed load would leave it behind and the next tap would push an identical URL and open nothing; a reload doesn't reopen the dialog either. The header "Upload receipt" button is `max-md:hidden` (the floating button replaces it; the empty-state button stays).
- "Clear all", "Clear filters" and the sheet's "Reset" keep the current sort (it isn't a filter chip).
- **Search** covers merchant, line-item descriptions and notes; a line-item-only hit is shown as "Line item: …" under the merchant (`itemHits`).
- **Amount filter** applies to the account's default currency only: while active, other-currency receipts are hidden (no FX), and the popover says so. `parseAmountInput` accepts the `number_format` style only and rejects the other ("12.50" in de-DE is invalid, not 1250).
- **Month groups** (header row with localized month and sum) only with date sorting; amount sorting is a flat list. The sum is in cent integers and hidden for mixed currencies. The month name uses `number_format` like the dashboard (`.claude/rules/dashboard.md`).
- **Mobile**: under `lg` (not `sm`: with the sidebar from `md` the controls don't fit one row between 768 and 1023 px) the Period/Amount/Type/Sort controls are replaced by a "Filters" button (badge = active filters except search; always rendered, `invisible` at 0, so the button keeps its width) opening a bottom `Sheet`. The sheet edits a draft copy and applies it on "Show n receipts" (`countFor` gives the draft's count); desktop controls apply immediately. A custom range is set only on desktop (the board has no range calendar on phones) but shows as a chip everywhere.
- **Stable toolbar**: sizes depend on the breakpoint only, never on the content (the toolbar jumped with the selection before). All controls are 28 px (`default` sizes; search `size="touch"`). Widths come from `StableLabel` in `receipt-filters.tsx`: an `inline-grid` with every possible label invisible in one cell, so a control is as wide as its longest label in the current language, whatever is selected — no magic widths. Layout: `lg`-`xl` search row above the controls row, from `xl` one row (`grid-cols-[minmax(0,1fr)_auto]`), no `flex-wrap`. The result row is always there, one line (`h-6`): chips left (`overflow-x-auto`), count right (`aria-live`, "n receipts" without filters, "n of m · sum" with); the table below doesn't shift on the first filter. The table is `table-fixed` (fixed preview/date/amount columns, merchant and "Line item" truncate with a `title`) so columns don't follow the content; below `sm` the date shows as a second line under the merchant (the fixed columns would leave the merchant ~46 px) and the date header shrinks to width 0 rather than `display:none` — the month rows' `colSpan={4}` would otherwise create a 4th auto column that halves the merchant's width.
- **Period is a popover, not a Select**: presets (list with check + `aria-pressed`) next to a range `Calendar`; a preset click sets and closes. The calendar uses `resetOnSelect` plus a local `draftRange`: the first click only sets the draft (nothing filters, nothing is written to the URL while picking, even if a range is already applied), the second click applies `period=custom` + `from`/`to` and closes — a single day is picked by clicking it twice, and clicking an applied single day clears to `all`. The draft is dropped whenever the popover opens or closes. The trigger's accessible name includes the value ("Period: This month"); it shows "Custom range" only while a custom range has dates. Focus goes into the popover by Base UI's default.
- **Amount button** always reads "Amount" (accessible name "Amount, active", `secondary` and an always-rendered dot — `invisible` when inactive, so the width never changes — while a bound is set); the values only appear in the chip. The popover's hint and error share one always-mounted `<p aria-live="polite">` (`min-h-[2lh]`), referenced by both inputs' `aria-describedby`; the currency is an `InputGroupAddon`.
- **Result count** is hidden until the receipts have loaded and while the account has none (`totalCount` is `null` until loaded); the row keeps its height.
- Deviations from the board: see `docs/ui-concept/README.md` (03 Phase 3).
- The summary line is the account-wide total, independent of filters, and is hidden when currencies are mixed (no wrong sum). Its amount is pre-formatted by `formatAmount` and passed into an ICU plural message via `t.rich()`, keeping the `<mono>` span inside the sentence.
- Delete uses an `AlertDialog` with a preview row: thumbnail, merchant, mono `date · amount currency`.
- **PDF rows**: a PDF receipt shows a static PDF icon tile (`ReceiptImage pdf`) instead of a thumbnail and never fetches the file — no full PDF download per table row. PDF rows have no hover preview at all (an enlarged icon adds nothing); the `HoverCard` still wraps the row, only its content is skipped (there's no thumbnail endpoint either way, see `.claude/rules/backend/receipts-api.md`).
- **Image cache** (`receipt-image.tsx`): images need a Bearer header, so they're fetched via `apiFetch` into object URLs. A module-level ref-counted `Map<receiptId, {promise, refCount, listeners}>` shares one fetch per receipt across row, hover card and zoom. Revoke only when `refCount` reaches 0. A rejected fetch drops its entry, so a transient failure isn't permanent. Consumers use `useReceiptImageUrl(id)`; `""` is a no-op.
- `refreshReceiptImage(id)` after a replace: fetch once, push the new URL to every listener, **then** revoke the old one. Deleting the entry instead would break consumers already mounted (the row behind the open dialog). No-op when nothing is mounted.
- **Hover preview**: `HoverCard` with each `TableRow` as trigger via `render`, delays 250/150 (Base UI's defaults suit links, not tables). No `tabIndex`/`aria-label` on rows — one tab stop per receipt; keyboard users open it by focusing the row's merchant `<button>` (focus bubbles up from that button, not from the row itself). Image `alt=""`, `object-contain` overriding `ReceiptImage`'s `object-cover`.
- **Detail**: a row click, or the merchant button (its click bubbles to the row), opens `ReceiptDetailDialog` instead of the old "…" menu — see `.claude/rules/frontend/receipt-dialog.md`. The open id is mirrored into `?receipt=<id>` via `history.replaceState`, read once as the initial `useState` value from `useSearchParams()` (not `window.location`: the dashboard links to `/receipts?receipt=<id>` via a client-side navigation, and then `window.location` is not updated yet at first render, so the dialog would not open and the effect would strip the param). `useSearchParams` needs a `Suspense` boundary; `ReceiptsPage` wraps `ReceiptsPageContent` in one (accepted cost). `replaceState` adds no history entries, so Back/Forward leaves the dialog alone — deliberate; reload, shared links and the dashboard's recent-receipt links are the use cases. Old `/?receipt=<id>` links work via the `/` redirect (see `shell-auth.md`). The detail is derived from the loaded list by id, not stored separately, so an edit or a delete keeps it in sync (or closes it) automatically. Dialog stacking order in `page.tsx`: detail < edit form < delete alert.
