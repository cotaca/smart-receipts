# Receipt dialog, zoom, date picker

The create/edit `Dialog` stays props-only: `defaultCurrency` comes from the caller's `useMe()`.

**Layout**: `DialogContent` is `sm:max-w-5xl max-h-[calc(100dvh-2rem)] flex flex-col` — no fixed height, the dialog is as tall as its content. Header and footer sit outside the scrolling area; the `<form>` is `flex min-h-0 flex-1 flex-col`. The body is one `grid md:grid-cols-[320px_minmax(0,1fr)] overflow-y-auto` wrapper: below `md` a single column; at `md+` the **fields column alone sets the row height** — the preview column is `md:relative` with an `md:absolute md:inset-0` inner flex column, so it never adds height and the image can be at most as tall as the fields column. The body only scrolls when the viewport is shorter than that.

**Preview column**: both modes open with the "Receipt image *" label in the same `h-5` label row as the fields column, so the preview's top lines up with the Merchant input (edit mode: label without `htmlFor`, replacing is its own button). The two image wrappers (edit, create preview) are sized to the image, not stretched — `max-h-64` on mobile, `md:max-h-none` so at `md+` they grow up to the (fields-column-high) preview column and then shrink as a flex item — with `min-h-32` and `overflow-y-auto`; the image is `w-full h-auto`. So a short receipt leaves no `bg-muted` band and the Replace/Zoom buttons sit right under it, a tall one scrolls. Only the empty create placeholder uses `md:flex-1` to fill the column; the "Choose file" button lives inside it. Accepted gap: `ReceiptImage`'s Skeleton takes the image's `className` and is 0px tall while loading, so the wrapper sits at its `min-h-32` until the image arrives — don't hardcode `h-full` on it, that breaks the `size-10` table thumbnail.

**OCR flow (create only)**: file selected → `extractReceipt()` → `scanning` → `review` (`"{n} of 3 fields found."` + a second line for line items, ICU-plural + Suggested/Not detected badges); both phases are derived, not stored. Fill a field only if OCR returned it — never overwrite typed input with `null`. Extraction errors are swallowed; manual entry must keep working. When `extraction.low_quality` is true, a separate `Alert variant="warning"` (amber, warning icon, `lowQualityTitle`/`lowQualityDescription`) sits above the fields-found/items-found alert, which always stays neutral `default` — kept apart on purpose so the counts don't read as part of the warning. Never `destructive`: it's a hint about the photo, not an error — nothing failed, the user just gets asked for a better picture. Deliberately not built: per-field source text and scan highlighting — confidence exists server-side but only feeds the line filter and the overall `low_quality` flag, never a per-field score, so anything more specific (e.g. "top of receipt", a bounding-box overlay) would still be fabricated copy — and the PDF review branch.

**Line items**: `items: ItemRow[]` (`ReceiptItem & { key: number }`, `key` from a `useRef` counter, React key only) seeded from `receipt?.items`. Extraction fills the table only when the user hasn't already added a row (`data.items.length && items.length === 0`) — same never-overwrite rule as the scalar fields. Lives in the right column below the header fields. Zero rows render `Empty` (`noItems` + one outline "Add item" button); one or more rows render the shadcn `Table` instead, with its own "Add item" button in the section heading — only one "Add item" button ever exists, never both. Qty/Unit price/Total inputs are `font-mono`/`inputMode="decimal"`/`type="text"` like Amount, each with a per-row `aria-label`; Qty/Unit price/Total columns are fixed-width (`w-20`/`w-28`/`w-28`) and right-aligned so the table doesn't overflow at `md` width. Changing Qty or Unit price recomputes Total (`(q*u).toFixed(2)`) whenever both parse; Total stays directly editable. The table scrolls after ~6 rows: a wrapper puts `max-h-86 overflow-y-auto` on the Table's own `[data-slot=table-container]` (it is `overflow-x-auto`, so it is the scroll ancestor — a max-height on an outer div would break `sticky`), and `TableHeader`/`TableFooter` are `sticky` with `bg-popover`, so column heads and the sum row stay visible. `max-h-86` = header 41px + 6 × 45px rows (`p-2` + `h-7` input + border) + footer ≈ 344px; re-derive it if cell padding or input height changes. A `TableFooter` row shows the item total in integer cents (`Math.round(Number(...) * 100)`, summed as integers to avoid float drift) — display only, never a submit gate, since deposits/discounts can legitimately make it differ from the receipt amount. When it does differ (and the amount field itself is valid), an `Alert variant="warning"` with warning icon below the table shows the absolute difference (`itemsSumMismatch`). It overrides the Alert's `role="alert"` with `role="status"` (tested): its text changes on every keystroke in Amount, and an assertive live region would interrupt each time. On submit, fully empty rows are dropped; every other row needs a description, a quantity `> 0`, and valid prices, else `invalidItemsError` and no request. Create sends `items`; PATCH **always** sends `items` — it's a replace-all, so a partial update would silently wipe rows if the field were left optional there too. Not built: blocking sum validation, dragging rows to reorder.

**Replace image (edit only)**: its own hidden file input, calls `replaceReceiptImage` immediately, not on Save — deferring re-creates the JSON/multipart mix the endpoint split avoids, plus a "text saved, image didn't" state. Success: `refreshReceiptImage(id)` → `onSaved(updated)`, dialog stays open. Failure: `replaceImageError`, no `onSaved`.

**Zoom**: a second `Dialog` on top, reusing the object URL already held (no second request), `sm:max-w-7xl` — it must stay wider than the parent dialog (`sm:max-w-5xl`) to read as a zoom at all. Named by an `sr-only` `DialogTitle`; `<img alt="">`. Escape closes only the zoom — its test asserts the zoom is gone **and** the Merchant field is still mounted, because both closing is the failure mode.

`receipt-zoom-view.tsx` (mounted only while open, so every open starts fresh):
- `{scale, x, y}` is one state object updated via functional `setView` — lets the wheel effect register once with `[]` deps.
- Wheel: `addEventListener("wheel", …, { passive: false })`, not React `onWheel` (passive at the root → `preventDefault` does nothing, the page scrolls behind).
- Wheel zooms on the cursor (`p = (cursor − offset)/scale`, `offset' = cursor − p·scale'`), buttons on the center. Scale 1–4; wheel factor per event clamped to [0.85, 1.15]; buttons ×/÷ 1.25.
- `clampOffset` and `containedSize` are pure, exported, numbers only — the honestly unit-testable part. Clamp against the **painted** size from `containedSize`, not the `<img>` box: with `object-contain` the box always equals the frame, which let tall receipts be dragged out of view.
- Drag: pointer events on the `<img>` + `setPointerCapture`; toolbar buttons are siblings, so no `stopPropagation`. Cursor from drag state, not `:active`.
- **`draggable={false}` is load-bearing** (native image drag swallows `pointermove`), plus `select-none`, plus ignoring `e.button !== 0` (a right-press strands a pan). Both regression-tested.
- A11y: zoom works from the keyboard via the three labelled buttons; panning is pointer-only. Keyboard panning is a named, unbuilt addition.
- Not unit-testable (jsdom): visual clamping, pointer capture, how the transform looks.

**Date picker** (shadcn `Popover` + `Calendar`, replaced the native date input):
- `purchased_at` is a `"YYYY-MM-DD"` string end to end; convert with `parseDateOnly`/`formatDateOnly` (local midnight). Never `new Date(str)` — the UTC parse shifts the day west of UTC.
- Trigger text follows `number_format` (`formatDate`); weekday/month names follow the UI language (`useLocale()` → date-fns locale). Future dates are disabled in the UI only; the backend accepts them.
- Month/year views are a hand-built `day | month | year` swap (all `w-64`), not `captionLayout="dropdown"` (native selects, useless for jumping decades). Opening resets to the day view on the value's month.
- The `MonthCaption` override goes through a `useMemo`'d `components` object — an inline component remounts each render and kills the `aria-live` month announcement. The caption button needs `relative z-10`: the generated nav bar overlays the caption row and eats clicks. Not unit-tested; re-check after regenerating `calendar.tsx`.
- The trigger is a `Button` (no `required`), so `handleSubmit` guards `!purchasedAt` itself (`selectDateError`).
